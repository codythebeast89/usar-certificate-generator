## Design Specificity Verdict

LLM assessment: The certificate artifact is highly specific (parchment, double-ruled border, watermark, script signatures, exact phrasing, 87 real insignia). The tool chrome is a fairly generic dark admin form. Redeemed by gamertag-style placeholders, QMC-specific title auto-swap, and the 30+ entry real unit taxonomy. Sharpest observation: PRODUCT.md's own evidence (Roblox group icons) suggests this reads as a milsim community's certificate mill wrapped in formal Army bureaucracy, played straight rather than winking at it -- right for Operate mode, but worth naming.

Deterministic scan: impeccable detect --json returned 5 advisory/quality findings, exit 0 (previously exit 2 -- likely because the one warning-severity finding, radial-halo, is now suppressed for the CLI path via last session's ignore-value entry). All 5 confirmed false positives: pre-existing one-off values already documented in DESIGN.md's "Accepted one-offs" notes.

The browser-injected overlay surfaced two things the CLI didn't: radial-halo again (the live-overlay detector doesn't consult the same config.json ignore-value suppression the CLI does -- a tooling inconsistency, not a new defect; same reasoning from last session applies), and em-dash-overuse (42 instances) -- traced to the "ABBR -- Full Name" pattern in generated <option> labels across the Division/Command-Group/Watermark selects, a domain-appropriate abbreviation-expansion convention, not prose dash overuse. Likely a false positive, flagged rather than silently dismissed.

Visual overlays: no user-visible overlay was left open -- Assessment B's injection ran inside its own automated, isolated browser session, not a window on the user's screen. Findings above are the captured console output only.

## Overall Impression

The certificate itself is the strongest part of this product by a wide margin. The tool that produces it has one confirmed data-integrity bug that undermines the whole premise (a wrong certificate can print silently), plus the generic-admin-form chrome problem the specificity verdict names. Biggest opportunity: close the gap between "the certificate is precise" and "the form that fills it out doesn't always preserve what you typed."

## What's Working

1. Live, always-correct preview via queueRender()'s coalescing loop -- both assessments independently named this the single strongest decision.
2. Logo-preview chips -- previewing left/right/watermark seals before render, backed by a cream disc, directly serves PRODUCT.md's hard insignia-accuracy requirement.
3. The One Object Rule, actually followed -- detector confirms no shadow exists anywhere except the certificate canvas.

## Priority Issues

[P0] Silent data loss on signatory title
- Why it matters: Editing "Left title line" then changing Division/Battalion silently discards the typed text and reverts to the course default, with zero indication. A wrong certificate could print and be handed to a real graduate with no one noticing.
- Fix: syncLeftSignatoryTitle() (js/app.js:538-545) fires unconditionally on every division change (js/app.js:561-568). Track whether the field still matches the last auto-set value and only overwrite when it does -- the same fallback pattern renderCertificate() already uses correctly.
- Suggested command: /impeccable harden

[P1] Graduate name has no overflow handling
- Why it matters: Script-font name drawn with unconstrained ctx.fillText (js/app.js:449-450) -- no measuring, wrap, or shrink, unlike the body paragraph. A long real username overruns the underline and crowds the border.
- Fix: Reuse the existing wrap-measuring approach to shrink the script font size when measureText(graduate).width exceeds a safe max.
- Suggested command: /impeccable harden

[P2] No status feedback during Download
- Why it matters: render -> toBlob -> CRC32 -> download with no intermediate state; a slow machine reads as a dead button.
- Fix: Disable the button and swap label to "Generating..." for the duration.
- Suggested command: /impeccable harden

[P2] Fieldset density in "Logos"
- Why it matters: 8 interactive controls in one legend group fails the ≤4 chunking check; densest section in the form.
- Fix: Split into "Seals" and "Watermark", or hide upload behind a toggle.
- Suggested command: /impeccable layout

[P3] Generic render-error copy
- Why it matters: "Render error -- check console" (js/app.js:513-516) assumes DevTools access a cadre member won't have.
- Fix: Replace with an actionable message.
- Suggested command: /impeccable clarify

## Minor Observations

- Placeholder text reads as leftover test data.
- "Expand preview" redundant with scrolling on mobile.
- .hint paragraph sits above the fields it explains rather than inline per-field.
- Reset uses both native form reset and a manual setTimeout override -- fragile dual mechanism.
- The four detector false positives from last session's audit remain correctly documented and unchanged -- no new drift since then.

## Questions to Consider

1. If the real audience is a milsim/roleplay community rather than literal Army cadre, should the interface keep playing the bureaucratic register completely straight, or would naming that context make the tool more honest about what it is?
2. PRODUCT.md already tracks five specific insignia known to be wrong -- should the UI surface that as a visible in-product signal, or is silence deliberate?
3. If a cadre member generates many certificates per graduating class, is a flat single-shot form still right, or does the usage pattern call for saved defaults / a batch mode?
